# M14: finish what M13 started

The Maki VM hits an IP misalignment inside opcode-table gaps during the
version-check arithmetic, so titlebar.maki never reaches findObject /
setXmlParam at runtime. The static runKnownScripts table is still in
place as a stop-gap so the chrome renders correctly, but real
Maki-driven widget state is the open work.

This document tracks the M14 checklist for that work. Each item links
to its own issue.

## Checklist

- [x] **M14a**, chase the IP misalignment in Maki dispatch (#37). Two stacked bugs: SkinRuntime did not retain script blobs so the VM's codeblock pointer dangled into freed memory, and every addScript passed cpuId=0 so all codeTable entries collided on scriptId=0. Fixed by retaining blobs in a parallel QList and reserving a unique id via assignNewScriptId. Real opcode dispatch runs now (~5900 ops/run before a downstream null-deref that M14b through M14f will sort out).
- [x] **M14b**, drop the static runKnownScripts titlebar hack once Maki drives chrome (#38). With M14k+M14l fixed the dispatch chain is stable, so the call no longer has to live inside `expandLayout` as a paint-readiness guarantee. Lifted it out: `runKnownScripts` is now a public Layout helper that callers opt into. The visual-regression harness (`tests/visual/render_layout`) calls it explicitly so the goldens still match (5/5 visual, 11/11 unit). Real apps that drive Maki via SkinRuntime no longer pay the static math; the actual scripts mutate widgets through `setXmlParam`. Replacing the static math with Maki dispatch in the visual harness is a follow-up (would need render_layout to instantiate SkinRuntime + dispatchOnScriptLoaded + dispatchXuiParams).
- [x] **M14c**, wire SkinView::update() to repaint when scripts mutate widgets (#39). Repaint callback registered with the runtime, marshalled to the GUI thread via QMetaObject::invokeMethod.
- [x] **M14d**, WASABIQT_FATAL_ASSERTS is non-fatal by default and hides VM bugs (#40). The flag itself was already wired up, this added the bonus from the issue: sid/ip/vsp are printed alongside every assert and guru meditation, plus guru meditations now also honour the fatal-assert flag.
- [x] **M14e**, replace %ls in fprintf trace with manual ASCII conversion (#41). Consolidated through wq_wide_to_ascii in wasabi-port-shim.h and applied to all bridge / bindings / guru output.
- [x] **M14f**, trace mode for VM dispatch with WASABIQT_TRACE_MAKI levels (#42). Levels 0/1/2/3 now controlled by the env var, with level 2 printing every dispatched opcode plus ip/vsp and level 3 adding the top of the operand stack.
- [x] **M14g**, stub Config / ConfigItem / ConfigAttribute bindings + non-object receiver fallback (#44). Method table resolves newItem, getItem, newAttribute, setData, getData. callDLF receiver-null fallback also catches non-SCRIPT_OBJECT typed values being dispatched as objects so a SCRIPT_INT idata aliased through odata as 0x1 does not crash the dispatcher anymore.
- [x] **M14h**, dedupe scripts on (file, param) so identical refs share a VM instance (#45). Refs that share the file path but differ on param= still get distinct VM instances, which is what Modern relies on.
- [x] **M14i**, bind a Config global so initAttribs() does not guru (#46). Done via M14j, the binding lives at dispatch time, not load time.
- [x] **M14j**, dispatch-time null/non-object receiver fallback (#47). Patches callDLF to substitute configDummy when a script dispatches on a null or wrong-type receiver. Gated on WASABIQT_CONFIG_FALLBACK=1. Drops a Modern skin run from 525 GURU_NULLCALLED messages to 0 and the test exits cleanly.
- [x] **M14k**, SCRIPT_FUNCTION_PARAMS bodies leave VSP unbalanced (#48). kKnownMethods grew 60 → 869 entries by scraping the upstream `{L"name", N, (void*)fn},` tables across the whole `api/` tree (script/objects, skin/widgets, wndmgr, timer, config, etc.). lookupNparams + the maki-bindings name match are now case-insensitive so .maki bytecode that uses setalpha/setAlpha/SetAlpha all resolve. setDelay nparams was wrong in BOTH tables (kKnownMethods + kMethods/maki-bindings.cpp) — fixed in both. WASABIQT_TRACE_CALLM=1 added in vcpu.cpp so future per-CALLM imbalances surface their resolved method name + nparams source. VSP-imbalance asserts dropped 2 → 0, all 11 unit tests still pass, GURU_NULLCALLED stays at 0.
- [x] **M14l**, heap corruption during sustained dispatch run (#49). Two port-shim bugs found via AddressSanitizer: (1) `WMALLOC(n)` treats its argument as a byte count, but upstream's `wasabi_std.cpp` says it's a wchar count and multiplies internally — so `WMALLOC(1)` for the SCRIPT_STRING init in vcpu.cpp:334 was allocating 1 byte, then writing 4 bytes of zeroed wchar, scribbling into the next chunk's malloc metadata.  (2) `MEMCPY` was implemented with libc memcpy, but upstream documents it as overlap-safe and PtrListRoot::removeByPos relies on that for in-place compaction — switched to memmove. Both fixed in `wasabi-port-stubs.cpp`. Sustained dispatch is now clean under ASAN.

## Done condition

All items checked off. titlebar.maki runs end to end through the
embedded VM, drives the chrome through findObject + setXmlParam, and
the runKnownScripts hack is gone.
